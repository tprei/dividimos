# Deslop pass — 2026-05-24

Audited the repo for slop (inline suppressions, advisory gates, dead code, debug
leftovers) and removed it by fixing root causes. No suppression was relocated or
widened.

## Gates: before vs after

`npm run lint` was effectively **advisory** — `eslint` with no `--max-warnings`
exited 0 while reporting 55 warnings, so CI's lint job passed without enforcing
anything. Typecheck (`tsc --noEmit`) and tests were already blocking. The fix
makes lint blocking with `--max-warnings 0`.

No `continue-on-error` or `|| true` advisory wrappers gate any checker. (The
`|| true` occurrences in workflows are cleanup commands — `supabase stop`,
sdkmanager license accept — not checker gates.)

## Root-cause fixes

- **Generated build artifacts were being linted.** 32 of the 55 warnings came
  from `android/app/build/.../native-bridge.js` (debug + release copies) — a
  gitignored Capacitor build output. Added `android/**` to the ESLint
  `globalIgnores` (the only JS there is generated). This is exclusion of a build
  tree, not silencing of source.
- **Unused imports/vars removed** (real fixes, not ignore patterns): `Loader2`,
  `haptics` in `bill/[id]/page.tsx`; dead `splits` blocks + now-unused
  `ExpenseSplit` import in `edit-draft.test.ts` (`hydrateFromServer` never
  accepted item splits); unused mock params `_val`×2, `_table`; unused
  `createTestGroup` import.
- **`as any` + `eslint-disable` removed** in `chat-expense-parser.test.ts` —
  rewritten as `makeResult({ amountCents: undefined as unknown as number })`,
  mirroring the sibling `null` test and still exercising the `?? 0` branch.
- **`jsx-a11y/alt-text`** fixed by adding `alt=""` before the spread in the
  `next/image` test mocks (a real `alt` prop still overrides via the spread).
- **Mock typing**: `vi.fn<(value: string) => string>(...)` so the encrypt/decrypt
  mocks accept their arg without a named unused param.

## Scoped rule overrides (project convention)

`@next/next/no-img-element` is a production-bundle performance rule (LCP,
bandwidth). Per the repo convention ("If a lint rule is genuinely wrong for the
project, change the ESLint config" — `CLAUDE.md`) and existing precedent in
`eslint.config.mjs`, it is scoped off in two narrow, justified places rather than
via inline disables:

1. `**/*.test.{ts,tsx}` — vitest stubs `next/image` with a plain `<img>` on
   purpose; the rule has no meaning in unit tests.
2. `src/components/bill/receipt-scanner.tsx` — previews a `URL.createObjectURL`
   blob of a user-captured photo with unknown intrinsic dimensions; `next/image`
   cannot size it to its natural aspect ratio without measuring, and a local blob
   cannot be optimized, so a plain `<img>` is correct.
